**OuAth design**:

 1. User in Claude Desktop pastes https://onchainchess-mcp.up.railway.app/mcp.
 2. Claude hits /.well-known/oauth-protected-resource, discovers AS, does DCR at /register.
  3. Claude opens a browser to /authorize?client_id=...&code_challenge=...&resource=....                                               
  4. Our consent page appears:
  - Claude wants permission to play chess on onchainchess as you.
  - Sign in with passkey to approve."   
  5. User taps "Sign in" → WebAuthn ceremony → we get credentialId + passkeyAddress.
  6. We call POST {chess-server}/api/auth/token (your existing bridge) → get a chess server token for that user. Auto-creates a chess account on first use (we'd need a small server-side tweak to support that for new passkey users, since today the bridge expects an existing username).
  7. We mint an auth code, store {code → user_id, chess_token, code_challenge, client_id}, redirect back to Claude.                    
  8. Claude exchanges code at /token (with PKCE verifier) → gets access + refresh tokens.                                              
  9. Claude calls /mcp with Authorization: Bearer <mcp_access_token> on every request.                                                 
  10. Each MCP tool handler: extract bearer → look up {user_id, chess_server_token} → call chess API with that chess token.
