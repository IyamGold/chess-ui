# Auth Gate: Passkey Authentication as Game Gatekeeper

## Context
Currently the chess game is accessible regardless of auth state — the PasskeyButton sits in the header as optional signup/login. When a user logs out and reloads, they still see the game. Games in localStorage aren't tied to user accounts, so different users on the same browser share the same game list.

**Goal**: Make passkey authentication the gate to the chess game. Unauthenticated users see ONLY a sign up / sign in screen.

## SDK Assessment

The existing passkey hooks (`usePasskeyAuth.js`) **already support** the desired flow:
- **Sign up**: `signup(username)` → creates WebAuthn credential → registers on backend `/api/register` → backend deploys smart account → returns address
- **Sign in**: `login()` → discoverable credentials → backend `/api/login` → returns account + username
- **Session persistence**: auto-restores from localStorage on page reload
- **Error handling**: surfaces backend errors (e.g. registration failures)

**What's missing**:
1. **Frontend**: No auth gate — game is always visible
2. **Frontend**: Games in localStorage aren't scoped per user
3. **Backend**: Username uniqueness check may not exist on `/api/register` (needs verification — outside this repo's scope)

## Implementation Steps

### Step 1: Scope Games Per User in gameManager.js
**File**: `src/utils/gameManager.js`

- Add `setCurrentUser(accountAddress)` that sets a module-level user prefix
- `INDEX_KEY` becomes dynamic: `chess_{address}_index`
- `GAME_PREFIX` becomes dynamic: `chess_{address}_game_`
- When no user is set (null), fall back to default keys (backward compat)
- Each user sees only their own games

### Step 2: Create AuthGate Component
**New files**: `src/components/AuthGate.jsx` + `src/components/AuthGate.css`

Full-page centered auth screen:
- App title ("Chess Board")
- Two buttons: "Sign Up" and "Sign In"
- Sign Up: prompts for username → calls `onSignup(name)`
- Sign In: calls `onLogin()` (browser passkey picker)
- Loading spinner during auth
- Error display with clear messages
- If login fails → suggest signing up

### Step 3: Restructure App.jsx
**File**: `src/App.jsx`

- If `!passkey.isAuthenticated`: render `<AuthGate>` only (no game, no header)
- If `passkey.isAuthenticated`: render current UI (header with username badge + logout, game views)
- On auth state change: call `setCurrentUser(passkey.account)` or `setCurrentUser(null)`
- On logout: reset view to 'list', clear activeGame
- Remove PasskeyButton from header, replace with inline username badge + logout button

### Step 4: Update App.css
**File**: `src/App.css`

- Remove standalone passkey button styles (move to AuthGate.css)
- Keep header auth badge styles for authenticated state

## Verification
1. `npm run build` passes
2. Open app unauthenticated → see only auth gate (no game visible)
3. Sign up with username → passkey prompt → game list visible
4. Reload page → session restored → game list visible (no auth gate)
5. Logout → back to auth gate
6. Sign in with passkey → game list with that user's games
7. Different user on same browser → sees their own (empty) game list

## Backend Note
The frontend will surface any error from `/api/register`. If the backend doesn't yet reject duplicate usernames, that check needs to be added server-side (outside this repo). The frontend is ready to display whatever error the backend returns.
