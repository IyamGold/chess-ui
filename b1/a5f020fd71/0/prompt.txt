# Add Online Play Frontend

## Context
The server backend is fully implemented (rooms, moves, WebSocket, auth, Stockfish WASM). The frontend only supports local games (browser-side Stockfish). We need UI to create/join online rooms and play via the server.

**Guiding principle:** Don't touch `Chessboard.jsx` at all. Build a parallel `OnlineChessboard` that reuses the same CSS and `Piece` component but has its own server-driven state management.

## Key Facts
- Server board format: flat `Array[64]` with same numeric piece types as client — no conversion needed
- Server legal moves: UCI strings like `["e2e3", "e2e4", "e7e8q"]`
- Server auth: `POST /api/auth/token { passkeyAddress, username }` → `{ token }` bridges passkey → server token
- WebSocket: server→client only (joined, move, gameOver, join, playerConnected/Disconnected). All actions via HTTP POST.
- All state changes (moves, joins) go through REST, not WebSocket

## New Files (6)

### 1. `src/hooks/useServerAuth.js`
Bridges passkey auth to server token automatically on login.
- On passkey `isAuthenticated` change → `POST /api/auth/token { passkeyAddress: account, username }`
- Stores token in `sessionStorage` (re-established each browser session via passkey)
- Returns `{ serverToken, isConnected }`

### 2. `src/hooks/useOnlineGame.js`
Core hook managing room state, WebSocket, and move submission.
- Takes `{ serverToken, roomId }`
- On mount: `GET /api/rooms/:id` → populates board, currentTurn, myColor, legalMoves, moveHistory
- Opens WebSocket `ws://host/api/rooms/:id/ws?token=xxx`
- On WS `move` event → re-fetches room state (gives us updated board + legal moves)
- On WS `gameOver` event → sets result
- On WS `join` event → transitions from waiting → playing, re-fetches
- `submitMove(uciStr)` → `POST /api/rooms/:id/move`
- `getValidMovesForSquare(index)` → filters server legalMoves by source square, returns target indices
- Returns `{ board, currentTurn, myColor, legalMoves, moveHistory, gameResult, status, submitMove, getValidMovesForSquare, room }`

### 3. `src/components/OnlineChessboard.jsx`
Self-contained board component for online games. Duplicates the ~85 lines of board rendering JSX from Chessboard (same CSS, same `Piece` component) but wires server-driven handlers:
- `handleDragStart` → calls `game.getValidMovesForSquare(index)` instead of local validation
- `handleDrop` → calls `game.submitMove(uci)` instead of local state update
- Opponent moves arrive via WebSocket → board re-renders from server state
- Promotion: uses `needsPromotion()` from `moveValidation.js` client-side just for the dialog UX; server validates the actual move
- Sound effects: `playMoveSound()`/`playCaptureSound()` on own moves, `playMoveSound()` on opponent moves via WS
- Shows "Opponent's turn..." indicator when not your turn
- Props: `{ serverToken, roomId, onBackToList }`

### 4. `src/components/GameSetup.jsx`
Replaces the inline setup JSX in App.jsx. Adds opponent type selection:
- **Local AI** — existing behavior (browser Stockfish)
- **Online Human** — creates room, goes to waiting screen
- **Online Stockfish** — creates room with server Stockfish, starts immediately
- Online options disabled with message if server not connected
- Also has a "Join Game" button that navigates to join screen
- Props: `{ onStartLocal, onStartOnline, onJoinGame, onCancel, isServerConnected }`

### 5. `src/components/JoinGame.jsx`
Simple invite code entry form.
- Text input + "Join" button
- `POST /api/rooms/join { inviteCode }` with server token
- On success → calls `onJoined(roomId, color)`
- Shows error on invalid/full room
- Props: `{ serverToken, onJoined, onCancel }`

### 6. `src/components/WaitingRoom.jsx`
Displayed after creating an online human room while waiting for opponent.
- Shows invite code in large text with copy-to-clipboard button
- Opens WebSocket to listen for `join` event
- On `join` → calls `onGameStart(roomId)`
- "Cancel" button to go back
- Props: `{ inviteCode, serverToken, roomId, onGameStart, onCancel }`

## Modified Files (2)

### 7. `src/App.jsx`
- Add `useServerAuth` hook alongside existing `usePasskeyAuth`

### 8. `src/App.css`
- Add styles for new components (GameSetup opponent selector, JoinGame form, WaitingRoom invite display)
- Keep all existing styles untouched
