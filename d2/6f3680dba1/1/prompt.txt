# MCP Server for OnChainChess

## Context
We want AI agents (Claude, GPT, etc.) to play chess on onchainchess.com as first-class players. Agents can't use the browser UI, so we're building an MCP (Model Context Protocol) server that exposes 8 tools mapping to our game server's REST API + WebSocket. The agent calls tools like `make_move` and `join_game` — the MCP server handles auth, HTTP requests, and WebSocket waiting internally.

## Architecture

```
Agent (Claude/GPT)  ←──stdio──→  MCP Server (Node.js)  ←──HTTP/WS──→  Game Server (Railway)
                                       │
                                  ~/.onchainchess-bot
                                  (persisted auth token)
```

## File Structure

```
mcp/
  package.json        # Dependencies: @modelcontextprotocol/sdk, ws
  index.js            # MCP server entry point — registers 8 tools
  api-client.js       # HTTP + WebSocket client wrapping game server API
  auth-store.js       # Token persistence to ~/.onchainchess-bot
```

## The 8 Tools

### 1. `create_account(username)`
- **Calls**: `POST /api/auth/signup` with `{ username }` (no auth header)
- **Side effect**: Saves `{ username, token }` to `~/.onchainchess-bot`
- **Returns**: Username confirmation
- **Errors**: Username taken (409), invalid format (400), account already exists on disk

### 2. `create_game(color)`
- **Params**: `color` — "white", "black", or "random" (default "random")
- **Calls**: `POST /api/rooms` with `{ color }` + auth header
- **Returns**: `{ roomId, inviteCode, color }`

### 3. `wait_for_opponent(room_id, timeout_seconds?)`
- **Flow**: First `GET /api/rooms/:id` — if already `playing`, return immediately. Otherwise open WebSocket, wait for `join` event.
- **Returns**: `{ opponent_username, opponent_color, status: "playing" }`
- **Timeout**: Default 300s

### 4. `join_game(invite_code)`
- **Calls**: `POST /api/rooms/join` with `{ inviteCode }` + auth header
- **Returns**: `{ roomId, color }`

### 5. `get_board_state(room_id)`
- **Calls**: `GET /api/rooms/:id` + auth header
- **Returns**: `{ fen, currentTurn, myColor, legalMoves, moveHistory, status, result, white, black }`

### 6. `make_move(room_id, move)`
- **Params**: `move` in UCI format (e.g. "e2e4", "e7e8q")
- **Calls**: `POST /api/rooms/:id/move` with `{ move }` + auth header
- **Returns**: `{ ok, fen, currentTurn, legalMoves, moveHistory, gameOver, result, reason }`
- **On illegal move**: Returns error with `legalMoves` array so agent can retry

### 7. `wait_for_turn(room_id, timeout_seconds?)`
- **Flow**: First `GET /api/rooms/:id` — if already agent's turn or game over, return immediately. Otherwise open WebSocket, wait for `move` or `gameOver` event.
- **Returns**: `{ fen, currentTurn, legalMoves, moveHistory, gameOver, result, reason }`
- **Timeout**: Default 300s

### 8. `resign(room_id)`
- **Calls**: `POST /api/rooms/:id/resign` + auth header **(NEW endpoint needed)**
- **Returns**: `{ ok, result }`

## Server-Side Change: Resign Endpoint

Add `POST /api/rooms/:id/resign` to `server/routes/rooms.js`:
- Validate room exists and status is `playing`
- Verify `req.user.id` is white or black player
- Determine result: resigner is white → "0-1", black → "1-0"
- Update room via existing `updateRoomResult` prepared statement
- Broadcast `gameOver` event with `{ result, reason: 'resignation' }`

This is the **only** server-side change needed.

## Auth Token Persistence (`auth-store.js`)

File: `~/.onchainchess-bot`
```json
{ "username": "claude-bot", "token": "uuid-here" }
```

- `loadCredentials()` — reads file, returns `{ username, token }` or `null`
- `saveCredentials(username, token)` — writes to file
- Token is never exposed to the agent in tool responses

Agents use `POST /api/auth/signup` (not passkey auth) since they can't do biometrics.

## WebSocket Strategy for Wait Tools

Ephemeral connections per wait call (not persistent):
1. Open WS to `ws://<serverUrl>/api/rooms/:id/ws?token=xxx`
2. Listen for target event(s) — `join` for wait_for_opponent, `move`/`gameOver` for wait_for_turn
3. On match → resolve and close WS
4. On timeout → reject and close WS

Both wait tools do an HTTP pre-check first to avoid unnecessary WS connections (handles race where event already happened).

## Server URL Configuration

Environment variable `CHESS_SERVER_URL`, read at MCP server startup.
- Default: `http://localhost:3001`
- Production: `https://onchainchess-production.up.railway.app`

For WebSocket, derive from HTTP URL: `http://` → `ws://`, `https://` → `wss://`
